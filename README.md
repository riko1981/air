# AirVision: мониторинг качества воздуха с дрона

AirVision - платформа для сбора, хранения и визуализации данных о качестве воздуха, получаемых с квадрокоптера. Проект показывает измерения CO2, CO, PM2.5, PM10, температуру, влажность, GPS-координаты, высоту полета, заряд батареи и статус дрона.

Система состоит из API-сервера, базы данных, веб-панели мониторинга и симулятора дрона. В текущей версии симулятор заменяет реальный дрон и отправляет тестовые данные по городам Казахстана.

## 1. Технология связи с дроном

Дрон собирает данные с датчиков качества воздуха и отправляет их на сервер в формате JSON. В реальной реализации на дроне может использоваться микроконтроллер или одноплатный компьютер, например ESP32, Raspberry Pi, Arduino с Wi-Fi/GSM-модулем или полетный контроллер с отдельным телеметрическим модулем.

Варианты канала связи:

- Wi-Fi - для локальных испытаний и демонстрации.
- 4G/LTE - для передачи данных с большого расстояния.
- Радиомодуль + наземная станция - если дрон не имеет прямого доступа к интернету.
- MQTT или HTTP API - для передачи телеметрии на сервер.

В этом проекте используется HTTP API. Дрон или симулятор отправляет POST-запрос на endpoint:

```text
POST /api/measurements
```

Локальный адрес API:

```text
http://127.0.0.1:8000/api/measurements
```

Пример JSON-пакета:

```json
{
  "city": "Алматы",
  "latitude": 43.222014,
  "longitude": 76.851248,
  "altitude": 85.5,
  "co2_ppm": 420.0,
  "co_ppm": 3.2,
  "pm25": 45.0,
  "pm10": 80.0,
  "temperature_celsius": 25.0,
  "humidity_percent": 45.0,
  "battery_level": 90.0,
  "drone_status": "active"
}
```

Файл `drone_simulator.py` имитирует работу дрона: генерирует координаты, значения датчиков и отправляет их на FastAPI-сервер каждые несколько секунд.

## 2. Модель данных

Основная модель измерения описана в `main.py` классом `Measurement`.

Поля измерения:

| Поле | Тип | Описание |
| --- | --- | --- |
| `city` | string | Город или регион измерения |
| `latitude` | float | Широта GPS |
| `longitude` | float | Долгота GPS |
| `altitude` | float | Высота полета дрона |
| `co2_ppm` | float | Концентрация CO2 в ppm |
| `co_ppm` | float | Концентрация CO в ppm |
| `pm25` | float | Частицы PM2.5 |
| `pm10` | float | Частицы PM10 |
| `temperature_celsius` | float | Температура воздуха |
| `humidity_percent` | float | Влажность воздуха |
| `battery_level` | float | Заряд батареи дрона |
| `drone_status` | string | Статус дрона |
| `timestamp` | datetime | Время записи в базе данных |

База данных хранит измерения в таблице:

```text
AirQualityMeasurements
```

По умолчанию используется SQLite:

```text
data/air_monitoring.db
```

Также предусмотрена поддержка SQL Server через переменные окружения.

## 3. Архитектура сайта и платформы

Общая архитектура:

```text
[Дрон / датчики]
        |
        v
[FastAPI backend]
        |
        v
[SQLite / SQL Server]
        |
        v
[Streamlit dashboard]
        |
        v
[Пользователь в браузере]
```

Поток данных:

1. Дрон собирает показания датчиков и GPS.
2. Дрон отправляет JSON-данные на FastAPI endpoint `/api/measurements`.
3. Backend проверяет данные через Pydantic-модель.
4. Backend сохраняет запись в базу данных.
5. Streamlit dashboard читает последние измерения из базы.
6. Пользователь видит карту, графики, статистику и архив измерений.

Основные компоненты:

| Файл | Назначение |
| --- | --- |
| `main.py` | FastAPI backend, REST API для приема и выдачи данных |
| `db.py` | Подключение к базе данных и SQL-запросы |
| `dashboard.py` | Streamlit-сайт с картой, графиками и таблицами |
| `drone_simulator.py` | Симулятор дрона и датчиков |
| `seed_data.py` | Заполнение базы демонстрационными данными |
| `requirements.txt` | Python-зависимости |
| `run_api.ps1` | Запуск API-сервера |
| `run_dashboard.ps1` | Запуск веб-панели |
| `run_simulator.ps1` | Запуск симулятора дрона |
| `.env.example` | Пример конфигурации |

## 4. API endpoints

FastAPI предоставляет следующие endpoints:

```text
GET /
```

Проверка работы API.

```text
POST /api/measurements
```

Прием измерения от дрона или симулятора.

```text
GET /api/measurements?limit=100
```

Получение последних измерений.

```text
GET /api/measurements/latest
```

Получение последнего измерения.

```text
GET /api/statistics
```

Получение общей статистики: количество измерений, средний CO2, PM2.5, температура и влажность.

Документация API после запуска доступна по адресу:

```text
http://localhost:8000/docs
```

## 5. Веб-панель

Веб-панель реализована на Streamlit и показывает:

- текущие показатели качества воздуха;
- карту измерений;
- тепловую карту загрязнения CO2 и PM2.5;
- графики изменения параметров во времени;
- сравнение с нормативами ВОЗ;
- архив последних измерений;
- экспорт данных в CSV.

Локальный адрес сайта:

```text
http://localhost:8501
```

Для входа используются переменные из `.env`:

```text
AIR_DASHBOARD_USERNAME
AIR_DASHBOARD_PASSWORD
```

Файл `.env` не загружается в GitHub, потому что содержит локальные настройки и пароль.

## 6. Запуск проекта

Создать виртуальное окружение и установить зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Создать конфигурацию:

```powershell
Copy-Item .env.example .env
```

Запустить API:

```powershell
.\run_api.ps1
```

Запустить сайт:

```powershell
.\run_dashboard.ps1
```

Запустить симулятор дрона:

```powershell
.\run_simulator.ps1
```

При необходимости заполнить базу демо-данными:

```powershell
.\seed_demo.ps1
```

## 7. Вывод сайта в интернет

Для демонстрации сайта можно использовать Cloudflare Tunnel:

```powershell
cloudflared tunnel --url http://localhost:8501
```

После запуска Cloudflare выдаст публичную ссылку вида:

```text
https://example.trycloudflare.com
```

Эту ссылку можно открыть с телефона или другого компьютера. Окно PowerShell с `cloudflared` должно оставаться открытым.

Рекомендуется выводить наружу только Streamlit dashboard на порту `8501`. API на порту `8000` лучше не публиковать без дополнительной авторизации.
